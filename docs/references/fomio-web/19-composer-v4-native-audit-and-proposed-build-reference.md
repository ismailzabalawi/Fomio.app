# 19 — Composer v4 native source audit and proposed build reference

Prepared 2026-09-30. **Proposed for review; not an approved build reference or Stage 1 authorization.** The source audit uses the Discourse commit `7b4f0970506fb0ce7d4b6a851d252ace418330c8` recorded in [09](09-composer-research.md). A subsequent signed-in browser check on [the live theme-36 preview](https://meta.fomio.app/?preview_theme_id=36) found a page `generator` meta tag reporting Discourse `2026.8.0-latest` at that exact commit. Theme 36 was in preview; this does not establish the site default theme or all server settings. Distinguish the source-backed findings below from the specific live observations recorded later.

## Native behavior for D3–D7

| Decision | Source-backed finding at the pinned commit | Build-reference disposition and remaining proof |
|---|---|---|
| D3 — draft conflict | A draft-save 409 with a description opens a dialog with **Reload** and **Ignore**. Ignore sets `draftForceSave` for a subsequent save; it does not copy text or immediately confirm replacement. The server checks draft sequence and can return 409. See [client save](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/models/composer.js#L1525-L1600) and [draft controller](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/app/controllers/drafts_controller.rb#L65-L98). | Use the native conflict route. Exclude r1's three-action conflict banner, Copy my text and replace confirmation from current acceptance. Reproduce a real conflict before claiming any recovery guarantee. |
| D4 — offline close | A dirty **cancel/discard** path opens the native Discard/Cancel modal and clears the draft after Discard. **Save and close** calls `_saveDraft(true)`, clears composer state and closes without awaiting the save promise. A failed draft save sets `draftStatus` to “drafts offline” unless a conflict message exists. See [close paths](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/services/composer.js#L1868-L1928), [modal](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/components/modal/discard-draft.gjs#L20-L46), and [save status](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/models/composer.js#L1561-L1597). | The live offline check below reproduced **text loss after Save and close** in this browser session. The r1 blocked-close Retry/Copy/discard design is excluded under D4, but native behavior now needs an explicit product decision before approval. |
| D5 — filled guided form switch | Form templates are conditional on `enable_form_templates`, category form IDs and composer context. The service snapshots form values before a draft save, with a comment that this is temporary until forms have a proper draft system. See [form gate](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/services/composer.js#L309-L324) and [form save](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/services/composer.js#L1943-L1963). Ordinary category topic-template application preserves nonempty edited reply text ([source](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/models/composer.js#L923-L952)); that is **not proof of filled form behavior**. | D8 defers guided-form activation. Exclude the custom switch dialog and answer-to-text conversion now. If forms are later in scope, reproduce switching with filled fields and verify persistence. |
| D6 — details, spoiler, code | The details plugin inserts native `[details]` syntax through a toolbar menu option ([source](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/plugins/discourse-details/assets/javascripts/initializers/apply-details.js#L5-L20)). The spoiler plugin adds a toolbar option for rich-editor toggle or `[spoiler]` wrapping, gated by `spoiler_enabled` ([source](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/plugins/spoiler-alert/assets/javascripts/initializers/spoiler-alert.js#L13-L45)). Core adds a direct code button only when `!capabilities.touch` ([source](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/lib/composer/toolbar.ts#L470-L480)). | Exclude the r1 details/spoiler/code sheets and reopen pattern. Verify actual mobile access to code formatting and whether both plugins/settings are active before mapping the native controls. Table/date decisions are separate. |
| D7 — failed link preview | Onebox loading acts on an anchor. On non-429 failure it marks the URL failed, calls `onResolve(null)`, and removes the loading class; the anchor is not replaced in that failure branch. 429 is retried after a delay. See [oneboxer](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/pretty-text/addon/oneboxer.js#L57-L110). | Preserve native link/preview behavior. The live invalid-domain check below showed the rich editor's native explanatory failure card and retained URL. Exclude r1's custom “Preview unavailable…” note and Try again control. Other failure types and loading appearance remain untested. |

## P-1–P-4 and LT

| Item | Finding and proposed treatment |
|---|---|
| P-1 | Native discard has **Discard** and **Cancel** actions ([modal](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/components/modal/discard-draft.gjs#L20-L46)). Use that flow; do not adopt r1's extra discard choices. |
| P-2 | The pinned English locale contains “Network Error” and “Please check your connection.” ([locale](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/config/locales/client.en.yml#L2753-L2768)). Reuse core network wording where that error surface actually appears; the locale's existence alone does not show which composer failure renders it. |
| P-3 | Core has a short “Draft saved!” toast after `_saveDraft(true)` and “drafts offline” status on failed save ([service](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/services/composer.js#L1943-L1977), [model](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/models/composer.js#L1561-L1597)). The model catches save errors and does not rethrow, so the service's success callback can still show the toast after a failed request. Treat a toast as **insufficient evidence of persistence**. Use native status semantics subject to LT, and reproduce this path before approving the copy. |
| P-4 | The composer uses native `CategoryChooser`, which is filterable ([composer](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/components/composer-container.gjs#L512-L523), [chooser](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/select-kit/components/category-chooser.js#L14-L28)). Its filter input has a placeholder but no explicit label or `aria-label` in that template ([filter](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/select-kit/components/select-kit/select-kit-filter.gjs#L154-L173)). The approved accessible name is **Search categories**. Check the rendered accessible name first; if absent, add a scoped accessible label through a supported seam, without changing every SelectKit filter globally. |
| LT | Core `draftStatus` has a title and icon, but the visible status text is rendered only in `desktopView` in both composer branches ([view](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/components/composer-container.gjs#L624-L647), [second branch](https://github.com/discourse/discourse/blob/7b4f0970506fb0ce7d4b6a851d252ace418330c8/frontend/discourse/app/components/composer-container.gjs#L801-L824)). This is a **source-level gap against Ismail's approved visible-text requirement** on mobile. Check 150% zoom, keyboard and touch behavior at the target version, then specify a scoped remedy before reference approval. |

## Live browser observations, 2026-09-30

These checks used the signed-in [theme-36 preview](https://meta.fomio.app/?preview_theme_id=36) in the Codex browser. They did not publish a topic or change site settings. The browser viewport was temporarily set to 390 × 844 for the narrow layout and restored afterward. A tab-scoped offline network emulation was restored afterward. This was a **single browser session**, not a device matrix.

| Area | Observed result | Limit |
|---|---|---|
| Version | Page `generator` meta reported `Discourse 2026.8.0-latest`, commit `7b4f0970506fb0ce7d4b6a851d252ace418330c8`; `discourse_theme_id` was `36`. | Preview does not identify the site's default theme or all setting values. |
| D4/P-3/LT offline draft | While offline, a temporary title and body showed “drafts offline” to accessibility inspection. At 390 px width, the visible status was a warning icon without text. **Save and close** closed the composer and displayed **“Draft saved!”**. After restoring connectivity, the temporary title did not appear in the latest-drafts menu; opening a fresh composer showed neither the temporary title nor body. | This demonstrates failure in the tested path; it does not prove every recovery route is absent. The menu contained one older, unrelated “Untitled draft,” which was opened and closed unchanged. No temporary offline draft remained in the menu. 150% zoom and a physical touch device were not tested. |
| P-4 category search | The open chooser's input had placeholder “Search…”, no `aria-label`, and no associated `<label>`; the browser exposed it as searchbox “Search…”. | It does not meet the approved “Search categories” name in this observed state. |
| D6 native controls | The toolbar showed Preformatted text; Options listed Hide details and Blur spoiler in this session. | A narrow browser viewport is not a touch-device test. The site's plugin/menu availability is observed, but insertion, editing and mobile touch access were not exercised. |
| D7 invalid link | In a temporary draft, `https://example.invalid/composer-audit` exposed **Load preview**. Activating it displayed the native message that the server could not be found and only a link would appear in the post. The URL remained a link in the failure card. The temporary draft was discarded, and the latest-drafts menu again showed only the older unrelated draft. | One invalid-domain failure was tested; rate limiting, timeouts, other URL types and published rendering were not. |

**Product choice needed for D4:** Is native Save and close's observed offline text loss acceptable for this scope, or should the design retain a recovery safeguard? Do not mark D4 or P-3 equivalent to a protected-save flow. **Implementation choice needed for LT/P-4:** identify a supported scoped way to show status text in the narrow composer and give its category search the approved accessible name. These choices precede build-reference approval.

## Proposed build-reference composition

For approval review, read these together in this order:

1. [The v4 roadmap](12-composer-v4-implementation-roadmap.md) and [composer agent guide](13-composer-agent-guide.md) for delivery sequence and native reuse rules.
2. [Frozen r1 design evidence](16-composer-v4-stage-0-r1.md) for visual intent and its captured acceptance/copy inventory. It remains immutable evidence, not wholesale approval of its interactions.
3. [D1–D10 direction](17-composer-v4-decision-update.md), then [approved r1 reconciliation](18-composer-v4-r1-reconciliation.md) and its [acceptance](composer-v4-r1-disposition/acceptance-disposition.csv) and [copy](composer-v4-r1-disposition/copy-disposition.csv) overlays. These take precedence for affected frames and wording.
4. This audit for source-backed native behavior and the runtime gaps that still prevent a final build-reference lock.

**Current scope:** Native Discourse behavior for D3–D7; D1–D2 remain for a later settings review; D8–D10 remain deferred. The five approved policies in doc 18 govern LT, P-1–P-4, copy and exclusions. Existing PM, staff, whispers, shared-draft and out-of-scope plugin functions must remain available where permitted. No theme-owned error copy or component replacement follows merely from an r1 screenshot.

**Before build-reference approval:** resolve the demonstrated D4/P-3 offline-close failure; verify relevant settings and the site's intended theme; reproduce D3 conflict, D6 touch-device controls, P-2's actual composer error surface, and LT at 150% zoom; implement or specify scoped LT/P-4 remedies and recheck their accessible results. D7 has one live failure case, while other cases remain open. D5 needs runtime proof only if guided forms enter scope. Record results against affected acceptance/copy overlay rows, then request explicit build-reference approval. **Stage 1 requires separate authorization after that review.**

## Native behavior

- One retained navigation model projects into one, two or three panes using available window width and Dynamic Type. Optional community navigation disappears before the topic list/detail pair collapses. Reading content retains the existing bounded column.
- Community scope and exact discussion/post identity survive presentation changes. Reply composition remains owned outside the adaptive view structure.
- The community chooser has one popover presentation binding; the system adapts it to a sheet in compact width. Changing width cannot switch between two competing presentation bindings and dismiss the chooser. Its filter remains outside the presented navigation hierarchy.
- The topic pane uses one stable content header for scope, Search and options. The native toolbar title/leading slots clipped scope text or dropped the selector after a permission failure, so they are no longer used for scope. The header uses `AnyLayout` to stack at accessibility text sizes while preserving chooser identity; selected names can wrap fully. Root Home hides the otherwise empty native bar and includes the wordmark in the compact header. Pushed category/search lists retain native Back. The wide sidebar also displays the wordmark.
- Create remains in options when there is no room for a direct action; direct Create requires an actual column width of 560pt, standard text and a visible native navigation bar. The default list-side split toggle is removed because the detail pane already exposes Focus/Show topic list.

## Independent browsing windows

The owner explicitly selected independent browsing windows on 20 October. `FomioWindow` owns a distinct `AppState` for each native `WindowGroup` scene; the iPad feed options expose **New window**. Tabs, routes, scope, search, selected topic, reading positions and presentation state are window-local. Cold-open URLs are queued at the mounted scene root until its state exists.

`AppWindows` shares configuration, per-user authentication, service and draft storage. Sign-in/out and expired authentication invalidate each window's viewer snapshots. Only the window that initiated sign-in executes its captured return intent. Identity revisions reject obsolete restore/sign-in completions; account changes close editors and cancel their autosave/upload work. Late posting results from a deactivated editor cannot recreate signed-out drafts or navigate another editor.

Notifications are shared across windows since the 2026-10-22 merge: one inbox, badge and device alert setup; a notification tap opens in the most recently used window only. See [architecture](architecture.md#notifications-with-several-windows--2026-10-22).

A shared permission failure now clears private snapshots and **pauses** every active window/tab search at its new viewer revision. A second visible scene cannot automatically resubmit its retained query and invalidate the first scene in return. Queries/scope remain available; explicit Retry restarts at page 1. Same-account reauthentication advances each window's search identity, allowing authorized recovery after sign-in. The controlled failure was reproduced in `b7d08b84` (four requests instead of three), then fixed and verified in `3ec0f82a` (22 focused passes) and `68869872` (176 integration passes, four live skips).

A saved draft has one editor across all windows, including while that editor is suspended for authentication. Another window receives an explicit already-open message. Closing releases ownership; resume reloads the latest saved writing rather than an old list-row copy. Discard refuses an owned draft. Draft revisions refresh lists across windows, and file cleanup preserves attachments belonging to open editors.

Seven focused contract tests passed in `90b9af58`, including ownership through authentication suspension and shared expiry. A first native multiwindow probe failed at startup because an empty scene root did not execute its state-initialization task; a mounted progress placeholder corrected it. The native New window journey then passed in `f7a19adf`: the AX hierarchy contains distinct native scenes retaining Finishing and All communities. That run also caught isolated-deinit allocator crashes in three unit cases; cleanup now listens for the actual hosting scene disconnect, avoiding deinitialization work and preserving editors when merely switching windows. The seven focused tests and all three normal iPad UI journeys subsequently passed (`90b9af58`, ten total, no warnings). The later close-window contract and strengthened two-scene assertion also passed in `8b6360f6` (eight window contracts plus native creation, nine passes). Its two modal-resize probes failed separately; the valid native Zoom follow-ups (`a3c84cd0` and `1572f0d8`) supersede those gesture-prerequisite failures. Shared authentication now reserves its entire callback/username-validation attempt, with identity-checked cleanup so an old attempt cannot clear credentials or session state belonging to a newer attempt; real live multiwindow consent remains unverified. No new backend API contract is introduced by scene ownership.

The DEBUG display wrapper now applies a fixed AX3 environment only when `--accessibility-text` is explicitly present. Normal launches leave native Dynamic Type traits untouched. The full-audit recheck is separate from forced-layout acceptance. Shared layout also uses a native corner-aware sidebar header inset to keep branding clear of floating-window controls; the peer’s `1e2a683a` native floating-window test verifies logo/control frame nonintersection, with its inspected capture in the shared evidence packet.

## System-bar mapping — 26 October 2026

The same toolbar mapping as [Duo readiness](iphone-duo-readiness.md) (2026-10-26) applies on iPad. The list column's bar carries the wordmark, Create, Search and feed options. The discussion bar carries Reply, then Save and Share, and the header holds only the one-line scope. An intermediate version kept Create, Search and options in the 300 pt list header, which split "All communities" mid-word; moving them to the bar replaced it. Tests on iPad Pro 11-inch (M5) / iOS 27.0 (fixture): 8 passed, 4 skipped, 1 failed — `testWideSidebarScopesAndExcludedDiscussionReturn` fails on an ambiguous `app.buttons["Home"]` query (sidebar row plus tab item). It fails at the same assertion on unmodified `bece043`, so the failure predates this change. The header check in `IPadReadinessUITests` now asserts a one-line scope plus the three bar buttons.

## Final acceptance and release limits

- Functional iPad window creation, scope parity/exclusion/return, narrow search/Back, chooser resizing/rotation, editor resizing/rotation and direct typing are verified at the recorded native/fixture layer. Existing passes are reused; no additional repeat run is needed.
- The [wide iPad observations](validation/2026-10-20-adaptive-native/ipad-wide-voiceover-manual-observations.json) verify native chooser Cancel and search/error/Retry/Cancel with VoiceOver on. The [narrow iPad observation](validation/2026-10-20-adaptive-native/ipad-narrow-voiceover-final-summary.json) passes one case at actual 375×508, Arabic AX3/dark, retaining scope/query and verifying recovery, VoiceOver-off cleanup and native window restoration. The human confirmed the failure announcement once. These native accessibility actions establish semantics; full rotor/swipe traversal remains unestablished, and lower AX3 content extends below the initial viewport.
- Full native predictive audits remain failed. The peer [native field reference](validation/2026-10-20-adaptive-native/native-field-reference/README.md) and [native Dynamic Type reference](validation/2026-10-20-adaptive-native/native-dynamic-type-reference/README.md) reproduce the reports separately; actual system-size growth and inspected text remain distinct passing functional evidence.
- Physical-device input, Full Keyboard Access/pointer checks and live multiwindow consent are not claimed. Production Universal Link delivery, ordinary-member deployed permissions and live posting remain separate release gates; fixture tests add no deployed capability assumption.

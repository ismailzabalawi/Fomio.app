# SwiftUI rich text prototype — 2026-10-19

This is an isolated experiment authorized by the user. The existing composer remains the app's composer. The prototype has no publish/upload actions, repository, saved-draft integration or authentication flow. Its text is memory-only. Launch a Debug build with `--rich-editor-prototype` (no `--fixture` argument is required). Omit the argument to use Fomio normally. The prototype screen and codec are compiled out of Release.

## Scope and ownership

`Fomio/Features/Editor/Prototype/SwiftUIRichComposerPrototype.swift` hosts iOS 26's attributed `TextEditor`, selection, Bold/Italic/Strikethrough controls, Rich text/Markdown switching, and Arabic/emoji, plain-prose and unsupported-block samples. Native selection and typing use SwiftUI APIs; no UIKit editor wrapper is used here. System formatting controls are hidden; the prototype owns semantic formatting attributes and derives font/strike appearance from them. Arbitrary pasted fonts/colors are not exportable formatting. Genmoji is distinct from Unicode emoji and blocks export rather than silently becoming plain text.

`PrototypeRichDocument.swift` is an independent, deliberately bounded prose codec. It imports simple `*`/`_` emphasis, `**`/`__` strong, `***`/`___` combined emphasis, `~~` strike, corresponding `[b]`/`[i]`/`[s]` tags, punctuation escapes, paragraphs and Unicode text. Supported nesting is bounded to 15 levels. Ambiguous or unfamiliar syntax is rejected rather than interpreted by a general Markdown parser. No claim of complete CommonMark/Discourse grammar support is made.

The document retains the exact source and the attributed projection for each line. Mode switching without semantic edits preserves source UTF-8 bytes, including spelling, blank lines and trailing newlines. After a rich edit, unchanged prefix/suffix lines (and equal-position middle lines when line count is stable) retain their source; explicitly changed lines serialize with Discourse BBCode and escaped ASCII punctuation. For example, bold `مرحبا 😀` becomes `[b]مرحبا 😀[/b]`. The Markdown tab exposes Discourse source, which can include BBCode; it is not restricted to pure CommonMark.

The exporter reparses a candidate and compares text/semantic marks line-by-line before accepting it. Failed conversion keeps the rich buffer and current mode; it does not replace writing with cached source. Formatting on newline separators is not persisted because it carries no character styling in this prose model. Whole-source preservation and normalization of explicitly edited lines are separate guarantees. This prototype does not preserve every original delimiter inside an edited line.

Unsupported content (links, code, headings/lists, quote attribution, uploads, polls, tables, plugin syntax, HTML/entities, mentions, shortcode emoji, autolinks, malformed markup and CRLF source) remains available in Markdown with an explanatory message; requesting Rich text shows read-only source and an Edit in Markdown action. Switching back preserves its source. Indentation or trailing whitespace that would change Markdown block/line-break semantics cannot be exported from rich text; writing stays in the rich buffer until corrected. This is conservative source protection, not rich support for those features.

## Undo/redo and paste follow-up — 2026-10-20

The user authorized work on history and paste within the separate prototype; the existing composer remains in place. `PrototypeEditorSession.swift` keeps snapshots of the rich buffer, semantic marks, selection/typing attributes, original codec/source, source selection and editing mode. The prototype's Undo/Redo controls restore the whole snapshot across typing, formatting, sample loading, paste and mode changes. In this experiment a mode change is itself an undoable action. A failed conversion is not a history action. New writing after undo discards the redo branch. Native typing updates within one second coalesce until an explicit action or focus change; the memory-only history retains the latest 100 actions. This is a prototype policy, not a production draft or document history format.

`PrototypePaste.swift` adds a checked import path through Apple's native `PasteButton` (iOS 16+). Plain text remains literal prose, including markup characters; the exporter escapes them rather than treating clipboard text as Markdown. RTF imports bold/italic font traits and strikethrough into semantic marks, with a notice that font/size/color/paragraph appearance adopts the editor's style. Links, underlining, attachments, RTFD, HTML and other unsupported representations are rejected before insertion. Where every item has a plain-text representation, an explicit **Paste plain text instead** action is offered. Markdown mode pastes plain clipboard text as exact source. Rich and source selection replacement are one history action; discontiguous source selections insert the replacement once. Provider order is retained and mixed supported/unsupported pastes are atomic. The importer limits payloads to 100,000 characters and RTF data to 1 MB.

Clipboard reads are asynchronous. A captured destination includes the document revision, mode and both selections; insertion rechecks it as one session operation. A canceled/replaced paste, or a document/selection change during loading, must not insert into the old destination. The prototype never polls or reads the clipboard on launch: the system Paste button initiates provider access. The app has no upload or publish path here.

The iOS 26 deployment target does not expose SwiftUI's `onPasteCommand` interception API, and `EnvironmentValues.undoManager` is read-only. The implementation uses a checked Paste button and session-level history controls rather than an editor wrapper or private API. Ordinary native editor paste still reaches the attributed binding: imported basic font traits are mapped to semantic marks, and known unsupported link/underline/structured/code attributes block export while preserving the rich buffer. This is not exhaustive clipboard-format or system-gesture parity. System shake/three-finger undo, hardware shortcut precedence while an editor is first responder, native Cut history, IME composition grouping, iOS 26 runtime behavior, VoiceOver and cross-app paste from real applications remain separate migration gates. Use the prototype's own Undo/Redo controls for the session-history experiment.

Apple's current [Undo and redo](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo) and [Edit menus](https://developer.apple.com/design/human-interface-guidelines/edit-menus) guidance was read on 2026-10-20. The prototype uses standard undo/redo symbols, contextual action labels, disabled unavailable actions and the system Paste control. Its explicit controls and bounded history are experimental; this is not a claim of complete platform editing parity.
